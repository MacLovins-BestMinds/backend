# Stage Zero — бэкенд

FastAPI: игровой движок (`/api/game`), авторизация (`/api/auth`) и AI-движок (`/api/ai`). Документация API — `/docs`.

## Запуск

```sh
cp .env.example .env      # заполнить ключи, см. ниже
./run.sh                  # или: docker compose up
```

Нужен системный `ffmpeg` (перегонка записей m4a → WAV). Без обязательных AI-ключей сервер не стартует и пишет, каких не хватает; запустить без ключей на моках — `AI_MOCK=1 ./run.sh`.

## AI-движок

| Что | Провайдер по умолчанию | Переменные |
|---|---|---|
| Распознавание записей (`delivery`, ответы жюри) | ElevenLabs Scribe v2 (REST, таймкоды слов, сам определяет язык) | `STT_PROVIDER`, `STT_MODEL`, `STT_LANGUAGE` (язык по умолчанию) |
| Живое распознавание для зала (`WS /api/ai/live`) | ElevenLabs Scribe v2 Realtime (WebSocket, VAD) | `LIVE_STT_PROVIDER`, `LIVE_STT_MODEL` |
| Голоса жюри (mp3 в `static/jury/`) | ElevenLabs `eleven_flash_v2_5` | `TTS_PROVIDER`, `TTS_MODEL`, `ELEVENLABS_VOICE_ID*` |
| Оценка содержания, вопросы жюри, refine | Gemini | `GEMINI_API_KEY`, `GEMINI_MODEL` |

### Где взять ключи

- **`ELEVENLABS_API_KEY`** — https://elevenlabs.io/app/settings/api-keys (нужны права на Speech to Text и Text to Speech).
- **`ELEVENLABS_VOICE_ID`** — https://elevenlabs.io/app/voice-library: выбрать голос, который хорошо говорит по-русски, добавить в My Voices и скопировать его ID (⋯ → Copy voice ID). Чтобы у трёх членов жюри были разные голоса, задайте `ELEVENLABS_VOICE_ID_STRICT`, `_KIND`, `_SKEPTIC`; незаданные берут общий `ELEVENLABS_VOICE_ID`.
- **`GEMINI_API_KEY`** — https://aistudio.google.com/apikey.

Ключи живут только на сервере: приложение шлёт звук в наш бэкенд, а не напрямую в ElevenLabs.

### Вернуться на старых провайдеров

```env
STT_PROVIDER=openai
STT_MODEL=whisper-1
LIVE_STT_PROVIDER=deepgram
TTS_PROVIDER=openai
TTS_MODEL=gpt-4o-mini-tts
OPENAI_API_KEY=...
DEEPGRAM_API_KEY=...
```

Провайдеры независимы: можно, например, оставить Scribe для записей и Deepgram для живого потока.

### Полезное

- `?mock=1` у любого `/api/ai/*` или `AI_MOCK=1` — примеры ответов без ключей.
- Ответы AI кэшируются на диске (`.ai_cache/`): повтор той же записи отвечает мгновенно. `AI_CACHE=0` — выключить, удалить папку — сбросить.

## Вход, история и живая оценка

- **Вход.** `POST /api/auth/register` и `POST /api/auth/login` (ник и пароль) отдают JWT. Приложение шлёт его в `Authorization: Bearer …`; с токеном раунд создаётся от имени вошедшего пользователя. Ник, заведённый раньше без пароля (`/api/game/auth`), можно закрепить паролем через `register` — история раундов остаётся.
- **История и прогресс.** `GET /api/game/progress` (нужен токен): все сыгранные раунды с баллами и привычками речи (темп, паразиты, паузы, повторы), средние за последние 5 раундов против 5 предыдущих, серия дней, до следующего звания, советы по цифрам. `GET /api/game/rounds/{id}/review` — разбор своего старого раунда.
- **Живая оценка содержания.** В `WS /api/ai/live` раз в ~7 секунд (когда набралось 12 новых слов) Gemini оценивает последние слова: по теме ли и есть ли содержание. Клиенту уходит событие `content` с баллом 0–100 и короткой подсказкой; промпт — `app/ai/prompts/live_check.md`.
- **Вход по почте.** `POST /api/auth/signup` (почта, ник, пароль) создаёт аккаунт и отправляет код; `POST /api/auth/verify` подтверждает почту и отдаёт токен; `POST /api/auth/resend` шлёт новый код; `login` принимает почту и не пускает, пока она не подтверждена. Сейчас подтверждение выключено (`EMAIL_VERIFICATION=false`): `signup` сразу отдаёт токен, код не нужен; чтобы вернуть код, поставьте `EMAIL_VERIFICATION=true`. Письма уходят через SMTP (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` в `.env`). Пока SMTP не настроен, код пишется в лог сервера и приходит в ответе (`dev_code`). Новые колонки в `users` добавляются при старте (`app/core/db.py`).
- **Вход через Google.** Приложение берёт Client ID из `GET /api/auth/config` и показывает кнопку Google, только если он задан (`GOOGLE_CLIENT_ID` в `.env`; пусто или заглушка из примера — кнопки нет). Google возвращает ID-токен, его проверяет `POST /api/auth/google`; первый вход сам заводит аккаунт, почта считается подтверждённой. Client ID создаётся в Google Cloud Console → Credentials → OAuth client ID → Web application, в Authorized JavaScript origins — адрес сайта (для разработки `http://localhost:8081`).
- **Презентация.** `POST /api/ai/fit-slides` (файл PDF или PPTX, тема, текст, аудитория) раскладывает питч по слайдам. PDF уходит в Gemini целиком (видит картинки), из PPTX берётся текст и заметки. Слайд про демо — всегда «Demo time.». Нужны `python-pptx` и `pypdf`.
- **Темп.** Игрок выбирает спокойный, обычный или быстрый (`pace` в `delivery` и в `WS /live`): спокойный не ругает за медленную речь, быстрый считает её ошибкой. Коридоры — `PACE_RANGES` в `delivery_metrics.py`.
- **Слова со временем.** В ответе `delivery` есть `words` (место слова в тексте и время) — по ним приложение подсвечивает текущее слово.
- **Уровни сложности.** Уровень (`easy` | `medium` | `hard`) задаётся при создании раунда (`difficulty` в `POST /api/game/rounds`) и хранится в раунде. От него зависят: тема (`level` в `content/topics.json`: 48 простых, 24 средних, 48 сложных; колесо — `GET /api/game/spin?difficulty=`), время (`LEVEL_TIMING`: подготовка 5/4/3 минуты, питч от 60/60/90 секунд), строгость разбора содержания (`CONTENT_LEVELS` в `app/ai/delivery.py`), вопросы и оценка ответов жюри (`QUESTION_LEVELS`, `ANSWER_LEVELS` в `app/ai/jury.py`). Тема дня берётся из простых. Уровень виден в истории раундов.
- **Ругань.** Бранные слова (английские, русские — кириллицей и латиницей, румынские) ищет `find_profanity` в `delivery_metrics.py`. В живом потоке сразу уходит событие `profanity`; в разборе это отметка в тексте и минус 8 баллов подачи за слово (не больше 32); жюри и разбор содержания отчитывают за неё (правила в промптах `content_score`, `jury_questions`, `jury_answer`, `live_check`).
- **Паразиты по смыслу.** «um», «э-э», «типа», «păi», «cum să zic» — паразиты всегда (на любом языке). «like», «so», «you know», «kind of», «deci», «adică», «gen», «знаете» бывают обычными словами: в разборе их судит Gemini по контексту (`filler_judge.md`), набор берётся по языку речи (`FILLER_SETS` в `delivery_metrics.py`); в живом потоке — та же проверка содержания. Если Gemini не ответил, разбор оценивает такие слова по положению во фразе.
- **Языки (en | ru | ro).** Язык речи распознавание определяет по записи само — `speech_lang` в ответе `delivery`; не определило (или язык не поддерживается) — язык речи из прошлого разбора этого раунда, иначе `STT_LANGUAGE` (по умолчанию `en`). На языке речи — всё о выступлении: расшифровка (в исходном алфавите), вопросы и голос жюри, оценка ответов и комментарии жюри (на языке ответа), советы и подписи разбора, подсказки живого зала. Оценка произношения Azure — только для английской речи. Язык интерфейса (заголовок `Accept-Language`, полный заголовок браузера тоже разбирается; хранится в `rounds.lang`, поле `lang` в `POST /api/game/rounds`) — только тексты тем, ошибок и прогресса (советы, названия навыков и режимов), на разбор он не влияет. `refine` и `fit-slides` пишут на языке текста игрока.
- **Переводы тем.** Темы переведены заранее: `content/topics.ru.json`, `content/topics.ro.json` (заголовок, задание, аудитория, выжимка, категория). Колесо, тема дня, создание раунда, история и разбор берут их по языку интерфейса; темы или поля нет, или английский оригинал поменялся (`source_hash`) — показывается английский. Добавили или поменяли тему в `topics.json` — запустите `docker exec backend-backend-1 python tools/translate_topics.py` (переведёт только новое и изменённое через Gemini, промпт `localize_case.md`) и перезапустите сервер; тест `test_every_topic_has_a_fresh_static_translation` напомнит.
